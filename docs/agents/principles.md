# 基本原则与沉淀

* 先读相关代码、测试和本地约束，再动手；沿用现有结构，改动范围与需求相称。
* 通用能力（格式/协议/解析/压缩/加密/日期）用成熟库，不手写底层。
* 只实现当前明确需要的功能，不为兼容多场景写大量分支。
* 本地存储结构是否兼容按具体功能和用户数据风险判断；不能仅凭“未上线”假设数据可丢弃。改格式前说明影响与恢复办法。
* 不因实现任务自行扩大验证范围；用户要求测试/验证时，运行与改动相称的检查并如实报告。未运行就明确标注，不把“代码已写完”说成“已验证”。
* 不改无关文件，不顺手重构；发现相邻问题先记录或单独说明。
* 工作区已有用户改动时不回滚、不覆盖，只在必要范围追加。
* 反复遇到的坑/用户反复提醒事项，沉淀为本目录最相关文件的可执行规则。
